# 离线地图

[English](OFFLINE_MAPS.en.md)

## 使用方式

在 APP「我的 → 离线地图」搜索城市并下载。开始导航前连接设备 Wi-Fi，保持 APP 前台，等待「设备地图已就绪」后再锁屏。城市地图保存在手机上；开发板只接收路线周边的一小部分地图。

手机能推送视频时，仪表优先显示实时导航画面。视频停止后，仪表使用收到的底图、路线和Wi-Fi 位置继续显示导航；视频恢复后自动回到投屏。地图缓存不等于离线算路，搜索目的地、规划和偏航重算仍由手机导航服务提供。

## 手机与设备各保存什么

| 位置 | 保存内容 | 生命周期 |
| --- | --- | --- |
| 手机 | 城市数据、字体、样式及已生成的路线图片 | 可在离线地图页继续下载、暂停或删除 |
| 开发板 | 当前路线周边地图、完整路线及最新位置 | 有界临时内存；导航结束或认证会话失效时清理 |

当前枣阳提供内置矢量城市包，保存后无需再次下载该城市数据；其他城市沿用地图服务的城市缓存。枣阳包约 28 MiB，实际占用会随着路线图片生成而增加。地图细节取决于数据源，不代表所有城市都有相同体积或同等道路覆盖。

手机准备路线地图时读取已有缓存。矢量数据先在前台生成路线所需图片，再选取设备窗口。设备容量不足时缩短前方覆盖范围，保持 17 级显示与图片质量；不会把整个城市传到开发板。路线超出已下载城市或缓存未完成时，应返回 APP 补充地图。

## 接入开发板

完整实现见 [ESP32-P4 开源工程](https://github.com/oounet/moto-esp32p4-example)的 `main/route_map_*.c`，使用 SDK 公开底层 C API。需要 **2026-10-08 revision 13 或更新的匹配二进制包**：`moto_map_port` 已扩展，必须同时更新头文件与静态库。不能只替换头文件。

目前地图端口接在完整 P4 根工程；独立 `examples/managed-terminal` 的 ABI 7 简化入口尚未暴露地图端口。已有简化入口工程不能直接将底层接口并发挂到 SDK 私有实例上，也不要启动第二个终端。

| 文件 | 负责内容 |
| --- | --- |
| `route_map_transport.c` | 非阻塞 TCP、认证 TLS 输入输出、超时与取消 |
| `route_map_store.c` | 有界暂存、验证后替换地图、JPEG 解码缓存、路线和位置事件 |
| `route_map_compression.c` | MZP1 解压、长度与 CRC 校验 |
| `route_map_view.c` | RGB565 底图拼接、路线与位置箭头 |
| `terminal.c` / `terminal_board.c` | SDK 单线程接线及视频/本地地图显示切换 |

创建 SDK 前配置端口：

```c
#include "route_map_store.h"

// cfg 是传给 moto_create 的 moto_config。
cfg.map = terminal_map_port();
cfg.route_navigation = cfg.map.max_bytes != 0;
```

在 SDK 所有者线程中转发 Wi-Fi 主实例中当前认证 owner 的事件给 `terminal_map_event(event)`，并周期调用 `terminal_map_poll(sdk)`。示例由 NimBLE host 每 20 ms 调用；TCP 每轮读取有界，不能无限阻塞 SDK owner 线程。显示任务调用 `terminal_map_draw`，其共享状态由互斥量保护。事件指针只在回调期间有效，保存路线或位置前必须复制。

热点仍使用导航投屏的 AP；地图另开 `192.168.4.1:5003` TCP，视频使用 UDP 5001。视频正常只证明视频端口可达，不能证明地图端口正常。TLS 使用当前加密 Wi-Fi 业务会话提供的临时凭据，导航、路线、owner 或会话变化后旧传输失效。不要记录密钥或使用公共固定密码。

## 整包压缩与连续发送

手机将地图包无损压缩后连续发送，传输过程中不等待每块地图的应用层确认。TCP/TLS 仍负责可靠传输、流量控制和认证。设备收满、校验、解压并提交成功后，统一返回完成确认，APP 才显示就绪。

- `MTP1` 包含路线与 256×256 地图图片；`MZP1` 是带原始长度和 CRC 的 zlib/DEFLATE 封装，没有文件路径或 ZIP 解包操作。
- 压缩收益不足时使用原始 MTP1，仍走连续传输；清晰度和级别不变。
- 断线后重新查询设备已接收位置，不能以手机已排队发送的字节数判断续传点。
- P4 示例地图上限 4 MiB，压缩前后都须符合限制。新旧地图及解压缓冲可能同时存在；分配保留额外 PSRAM，JPEG 缓存最多 20 张。无需写入 Flash。
- 校验失败保留当前可用底图，不显示未完成数据。位置过期后停止移动并标记暂停，不推算虚假位置；缺图区域显示灰底，仍保留有效路线和 HUD。

## 联调与排障

1. **亮屏投屏正常但地图未就绪：**检查 TCP 5003 监听、同网段、手机局域网权限及地图 TLS 状态。不要仅检查视频 UDP。
2. **下载过城市仍在准备：**城市数据与路线图片不同；第一次经过新路线需要本地生成图片。保持 APP 前台，完成后可复用。
3. **锁屏后只有 HUD 或路线：**确认地图已完成传输、Wi-Fi 位置仍新鲜、当前路线在城市覆盖范围内。首次准备中锁屏可能中断渲染。
4. **长路线或偏航后缺底图：**检查移动窗口更新、Wi-Fi 连接、剩余存储和新路线缓存；新区域可能需要回到 APP 前台。
5. **结束后仍有旧画面：**检查 NAV_END、CLOSED、UNPAIR 与 owner 切换是否清理旧地图/位置，以及迟到回调的代次校验。

目前 iPhone → P4 的静态路线传输已实测，用户确认整包传输显著提速；这不代表所有机型均达到固定吞吐。Android 真机、持续道路骑行、长时间锁屏、偏航重算、驶出缓存、断线续传及内存压力仍须按目标产品验收。不要用构建通过代替这些检查。
